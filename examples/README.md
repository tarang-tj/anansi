# Example structured output

Regenerate with `uv run python scripts/generate_examples.py`. Everything here is
produced by running the real pipeline over real HTML — nothing is hand-written.

| File | What it shows |
|---|---|
| `healthy-run.json` | A clean extraction. 12 records, every established field populated. |
| `broken-run.json` | The same collector after a layout change. **Still HTTP 200, still 12 records** — but `hours` is `null` on every one. |
| `verdict.json` | What the classifier concluded and the baseline evidence it used. |
| `heal-prompt.txt` | The repair instruction generated from that evidence, sent verbatim to `bdata scraper heal`. |

## The point of the pair

Open `broken-run.json` and look at it the way a downstream consumer would:

```json
{
  "name": "Aldermoor Community Food Pantry",
  "address": "14 Cobbler Lane, Aldermoor, Mercer Hollow County, State of Serenoa 00001",
  "phone": "(555) 555-0101",
  "hours": null,
  "services": "Groceries, Diapers, Hygiene kits"
}
```

Nothing about that record announces a failure. The request succeeded, the record
count is unchanged, the org is real, and five of six fields are correct. A
pipeline checking status codes sees a green run. A dashboard renders a pantry
with no opening hours, which is indistinguishable from a pantry that genuinely
did not publish them.

`verdict.json` is how Anansi tells the difference:

```json
{
  "state": "selector_break",
  "affected_fields": ["hours"],
  "reasons": ["'hours' populated in 0% of records, down from 100% across 6 runs"]
}
```

Uniformity is the tell. Every record lost the same field at the same moment,
and that field had been populated 100% of the time across the previous six
runs. One pantry dropping its hours would have been content change and would
**not** have been healed.

## The generated heal prompt

`heal-prompt.txt`, 504 characters, written by the system rather than a person:

> The 'hours' field(s) stopped extracting and now return empty. 'hours' was
> populated in 100% of records across 6 prior runs, with values like
> "Mon-Fri 9am-4pm"; "Mon-Fri 9am-4pm, Wed 9am-7pm"; "Mon-Fri 10am-2pm". The
> page still loads normally (HTTP 200, 30201 bytes of HTML). These fields still
> extract correctly: address, eligibility, languages, name, phone, services. The
> information is still on the page but has moved. Re-locate the 'hours' field(s)
> and restore extraction to the original output shape.

Naming the six intact fields is deliberate. It tells the healer the failure is
localised, which scopes the repair to one selector instead of inviting a
regeneration that could lose extraction logic that was working.
